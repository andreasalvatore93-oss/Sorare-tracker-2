b) Fix link Telegram: commit SHA invece di branch (commit ff9e54e912)
   BUG REALE osservato dall'utente: la seconda run (yannic10) ha mandato
   un link che apriva ancora il report della run precedente (temha58).
   Causa: raw.githack.com cacha aggressivamente gli URL basati su branch
   ("main") -- con un file a percorso fisso sovrascritto ogni run, quello
   e' esattamente il caso peggiore per quella cache. Fix: lo step "Save
   log" espone commit_sha (git rev-parse HEAD dopo il commit) via
   $GITHUB_OUTPUT, e il link Telegram usa quel commit SHA al posto di
   "main" -- URL diverso ad ogni run, mai una cache stantia.
   Verificato su run reale (31408160033): commit SHA nel push = commit SHA
   nel link, titolo dell'HTML scaricato = manager di QUELLA run.
