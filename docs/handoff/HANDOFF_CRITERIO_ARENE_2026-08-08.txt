3. COSA HO TOCCATO -- COME SI RILANCIA
=====================================================================
In generate_arene_efficienti, ogni tipo produce ancora 'resa' (essenze
attese, come sempre). Con ARENA_CRITERIO='capitale' il CONFRONTO fra tipi
usa resa/COSTO_INGRESSO[tipo] invece di resa nuda; la resa vera (essenze) e'
comunque quella che entra nella formazione scelta, il criterio cambia solo
QUALE tipo si sceglie a ogni passo. Il criterio di stop resta "il migliore
possibile non rende piu' niente" (matematicamente equivalente in entrambi i
casi, verificato: COSTO_INGRESSO e' sempre positivo, quindi dividere non
cambia il segno).

Rilancio locale (nessuna query se non serve il top-up L10, che gira solo
con SORARE_COOKIE impostato):
  ONLY_LEAGUES=mls,kleague ARENE_EFFICIENTI=N ARENA_CRITERIO=capitale python generatore_formazioni/build_formazione_globale.py

Rilancio GitHub Actions (formazione_giornata.yml), nuovo input arena_criterio:
  gh workflow run formazione_giornata.yml -f arena_criterio=capitale -f escludi_lockate=1 -f arene=N ...

0b -- criterio di stop verificato esplicitamente (non solo assunto):
COSTO_INGRESSO[tipo] e' sempre un intero positivo (200/300/800 nelle chiavi
usate, mai 0 ne' negativo in nessun punto del codice). Dividere una
quantita' per un numero positivo non cambia il segno: "migliore[0] <= 0"
resta la condizione di stop corretta con ARENA_CRITERIO='capitale' tanto
quanto con 'assoluto'. Verificato anche empiricamente: un run locale con
ARENA_CRITERIO=capitale e ARENE_EFFICIENTI=10 (mazzo locale, mls+kleague) si
ferma regolarmente all'ultima resa positiva, nessun loop ne' arresto
anomalo, mix diverso da 'assoluto' come atteso (vedi esempio sotto):

  assoluto: uncapped, 260, 260, 260, 260, 260, 220, 260, 220   (7x260, 2x220)
  capitale: uncapped, 260, 220, 260, 260, 260, 260, 220, 260   (6x260, 2x220,
            ma la 220 entra alla POSIZIONE 3 invece che alla 7: il criterio
            capitale la promuove prima, come atteso dalla teoria del brief)

Questo e' un run LOCALE di verifica (dati di oggi mattina, senza
ESCLUDI_LOCKATE, non e' il Passo 1 vero): serve solo a dimostrare che
l'interruttore FUNZIONA e produce il tipo di spostamento atteso. Il
confronto vero (Passo 1, ESCLUDI_LOCKATE=1) e' nella sezione 6.
